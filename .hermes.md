# VSS Hermes Project Context

You are running Hermes directly on the VSS host, not inside a NemoClaw or
OpenShell sandbox.

## Runtime Assumptions

- You have direct access to this repository, Docker, Docker Compose, `uv`,
  `ngc`, and VSS service APIs.
- Use normal host paths and host networking.
- Do not assume `/sandbox`, `host.openshell.internal`, OpenClaw dashboard
  tokens, or NemoClaw network policy.
- The VSS Orchestrator MCP server is optional for standalone Hermes. Prefer
  the VSS skills' direct host workflow unless the user explicitly configured
  MCP.

## First Checks

Before deploying VSS:

1. Confirm the repository root is the current working directory.
2. Confirm `NGC_CLI_API_KEY` is available for local NIM/artifact pulls.
3. Check GPU/Docker readiness with the relevant VSS skill.
4. Use dry-run compose generation before starting containers.

## Skill Use

VSS skills are expected to be installed or linked into Hermes under
`~/.hermes/skills/vss`. Use the skills for deployment, search, alerts,
summarization, calibration, video IO, and analytics workflows.

For deployment requests, use the `vss-deploy-profile` skill. For direct
questions about video content, use the video query/summarization skills.
